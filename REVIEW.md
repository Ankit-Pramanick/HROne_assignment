# REVIEW.md

Listed every defect found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | (a) Direct `.replace()` without IST conversion fails for UTC datetimes; (b) Flawed grace period logic: `minutes = int(diff / 60); return minutes if minutes > 10 else 0`. At 10m 01s late (e.g. 09:40:01 for a 09:30 shift), `int(601/60) == 10`, and `10 > 10` is False, returning 0 instead of 10 (violates R2); (c) Does not support overnight shifts crossing midnight. | Test with punch-in at 09:40:01 IST against a 09:30 shift. Expected 10 late minutes per R2 contract example, but function returned 0. | Converted `punch_in` to IST, computed exact total elapsed seconds `diff_sec`, checked `if diff_sec > 600: return int(diff_sec // 60) else 0`, and handled overnight shift start date calculation. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies Banker's rounding (round-half-to-even) instead of the half-up rounding explicitly required by R4. | Test rounding edge cases ending in 0.005 (or rounding 2.5 to 0 decimals yielding 2.0 instead of 3.0). | Implemented `round_half_up()` using `Decimal` with `ROUND_HALF_UP` quantized to `Decimal("0.01")`. |
| 3 | `compute_overtime` (lines 44-47) | (a) Missing the 30-minute minimum threshold required by R3 (any positive minutes were returned as overtime); (b) Assumed shift end was on `date_str`, failing for overnight shifts (`shift_end <= shift_start`) where the shift ends on the following calendar day. | Punch-out at 18:35 for an 18:30 shift end produced 5 minutes overtime instead of 0; overnight shift end calculation was incorrect. | Enforced `diff_min >= 30` before counting overtime; for overnight shifts, advanced the shift end date by 1 calendar day. |
| 4 | `health` (lines 72-74) | Returned hardcoded `{"status": "ok"}` without checking if MongoDB was alive and reachable, violating the readiness probe contract. | Stopping MongoDB still resulted in `GET /health` returning 200 OK instead of the required 503. | Added `client.admin.command("ping")` inside a try-except block, raising `HTTPException(status_code=503)` if MongoDB does not answer. |
| 5 | `create_employee` (lines 77-85) | (a) Check-then-insert race condition (`find_one` followed by `insert_one`) allows duplicate `emp_code` under concurrency; (b) Used naive `datetime.now()` instead of UTC BSON datetime; (c) Returned `created_at` as a Python datetime rather than integer epoch milliseconds; (d) Missing validation that `shift_start != shift_end`. | Concurrent POST requests with the same `emp_code` created duplicates; response showed ISO datetime string rather than integer milliseconds; equal shift times were accepted. | Added unique index on `emp_code` and caught `DuplicateKeyError` to return 409; validated `shift_start != shift_end` in Pydantic validator; stored UTC datetime and converted `created_at` to epoch milliseconds. |
| 6 | `list_employees` (lines 88-96) | (a) Pagination skip was `page * page_size`, meaning page 1 skipped the first 20 records; (b) `total` counted the entire collection instead of the filtered subset; (c) Missing sorting by `emp_code` ascending; (d) `created_at` not serialized to epoch ms; (e) Missing `page_size` max constraint (100). | `page=1` returned items 21-40; filtering by department showed total collection count; records were returned in indeterminate order. | Changed skip to `(page - 1) * page_size`; passed filter query `q` to `count_documents(q)`; added `.sort("emp_code", 1)`; serialized `created_at` to epoch ms; added Query constraint `le=100`. |
| 7 | `punch_in` (lines 99-121) | (a) Did not check if employee exists, throwing a 500 `KeyError` on `emp["shift_start"]` instead of returning 404; (b) Accepted arbitrary status strings (including `ABSENT`/`LEAVE`); (c) Derived `date` from naive local date without IST timezone and overnight shift logic (R1); (d) Check-then-insert race condition on `(emp_code, date)`; (e) Injected MongoDB `id` into response, violating contract; (f) Returned BSON datetime instead of epoch ms; (g) Allowed seconds-looking timestamps and failed to truncate to whole seconds. | Punching in for non-existent employee crashed with 500; concurrent punch-ins created multiple records for the same employee and date; response contained forbidden `id` property. | Added 404 check for employee; validated status against `("PRESENT", "WFH", "ON_DUTY")`; implemented R1 attendance date logic with IST timezone; enforced unique compound index `(emp_code, date)` and caught `DuplicateKeyError` returning 409; removed `id` field; converted to epoch ms and truncated to whole seconds. |
| 8 | `list_attendance` (lines 124-150) | (a) Loaded all matching records into Python memory with `list(db.attendance_logs.find(q))`, which degrades and exhausts memory on 100k records; (b) In-memory sort by date descending only, missing tie-breaker `emp_code` ascending; (c) Missing validation for `date_from > date_to` (must return 422); (d) Injected forbidden `id` property; (e) Did not serialize dates in `punch_in`, `punch_out`, or `history` to epoch ms; (f) Crashed on legacy documents missing `history` or `half_day`. | Explain plan would show full collection load; `date_from=2026-07-10&date_to=2026-07-01` returned 200 with empty list instead of 422; response contained forbidden `id` field. | Streamed records via MongoDB cursor using `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`; added 422 check for `date_from > date_to`; removed `id`; serialized all instants to epoch ms; defaulted missing `history` to `[]` and `half_day` to `False`. |

### What was examined and decided was NOT a defect:
- **String representation for shift times and dates:** Storing `shift_start` and `shift_end` as `"HH:MM"` and `date` as `"YYYY-MM-DD"` is intentional design per `DATA_MODEL.md`. They represent calendar concepts and local IST times rather than universal instants.
- **Natural key identification via `emp_code`:** The absence of MongoDB ObjectId references in the API is deliberate; `emp_code` is the business identifier and `_id` is kept internal.
- **PyMongo returning naive datetimes:** PyMongo returns naive UTC datetimes by default. Handling them explicitly at the boundary by attaching `timezone.utc` before conversion is standard practice.
